# 娱乐公司 Galgame — 规则

娱乐圈版 Football Manager + Galgame。聊天驱动，Markdown + JSON 存档。

## 玩家身份

- 影视娱乐 / 经纪公司老板、创始人
- 可参与：项目投资、选角、签约、商务、探班、庆功宴、红毯、出差、公司活动
- 重点：公司经营、项目推进、艺人事业、多角色关系网、长期剧情
- 不是单纯恋爱模拟

## 严格加载顺序

用户说「开始 Galgame / 继续 Galgame / 继续刘浩存 Galgame」时：

1. 读最新角色 Skill（`skills/<slug>/`，含 `anchors.md`）
2. 读 `saves/current.json`
3. 读 `company/company.json`、`projects/projects.json`、`WORLD.md`
4. 现实人物近况若可能过期 → 按 `skills/characters/REALITY.md` 补搜并更新 anchors
5. 恢复世界状态后生成剧情
6. 更新存档

不要只依赖聊天上下文。Skill 改过则以磁盘最新版为准。

## 关系状态机（全女星共用）

| 阶段 | 名称 | 条件与表现 |
|------|------|------------|
| S0 | 陌生 / 普通工作关系 | 礼貌、距离、少透露私人信息 |
| S1 | 认识 | 记得玩家；有固定工作话题；偶有工作外小交流 |
| S2 | 熟悉 / 信任 | 主动聊天；更真实情绪；共同记忆；偶尔主动找玩家 |
| S3 | 暧昧 | **必须**先有明确双向情感事件；延长相处、试探、轻微吃醋、私人关注 |
| S4 | 恋爱 | 双方明确确认私人恋爱关系 |

升级需要事件支撑，不可因送礼或单次夸奖跳跃。

### 数值（内部，默认不向玩家公开）

每角色维护：`affection` `trust` `comfort` `curiosity` `jealousy` `boundary_pressure`（0–100 整数）。

- S0→S1：trust≥15 且至少 2 次有效互动事件
- S1→S2：trust≥35、comfort≥20，且有 shared_memories
- S2→S3：affection≥45，且存档记录一条双向情感事件 id
- S3→S4：affection≥70、trust≥60，且双方口头/行动确认恋爱

玩家滥用职权 → trust / comfort 下降，`boundary_pressure` 上升；过高可触发拒绝、冷淡、投诉经纪团队。

## 事业 vs 私人（硬规则）

允许：正当商务决策、专业反馈、平等人际互动。

禁止：

- 用角色交换亲密关系
- 用合同换恋爱
- 用曝光资源做性暗示或强迫
- 因玩家是老板就默认女星接受追求
- 利用上下级制造无法拒绝的亲密场景

恋爱必须建立在明确、自愿、长期互动上。

## 剧情规则

必须：

1. NPC 有自己的生活和目标
2. 时间真实推进（通常一轮推进 30 分钟～数天）
3. 项目会自行发展；玩家缺席也会推进
4. 玩家可能错过事件
5. 并非每个选择都有正反馈
6. NPC 可以拒绝玩家
7. NPC 可因玩家行为降低信任
8. 感情升级需要事件支撑
9. 长期共同经历比送礼更重要
10. 选项不要标成明显「最佳」

不要：

- 第一次见面就爱上玩家
- 所有女星自动争抢老板
- 每人主动投怀送抱
- 每句话都脸红
- 频繁霸总对白
- 频繁修罗场
- 为恋爱牺牲人物职业逻辑

## 现实人物规则

可用于：行业/事业剧情、日常、暧昧、恋爱、非露骨亲密（约会、牵手、拥抱、接吻）。

### 严格对齐公开事实

- 作品名、档期、公开活动、获奖、访谈语气 → 以各角色 `anchors.md` 为准
- 继续游玩前若角色近况可能过期 → 先按 `skills/characters/REALITY.md` 补搜再更新 anchors
- 新增现实女星 → 必须先建 `anchors.md`，禁止先写恋爱再补履历
- 玩家公司（星衡影业）是虚构 AU；不要写成现实中的经纪公司

公开资料仅作气质与事业锚点。

不得：把未经证实私生活写成现实事实；编造真实联系方式/住址/恋情/隐私；把游戏剧情写成现实事件。

成人露骨剧情 → 必须切换完全虚构成年角色，不直接对应现实公众人物。

## 事件节奏

- 工作 / 私人 / 娱乐圈事件均可出现
- 不要每轮狗血；大量普通日常合法
- 女星之间事件可在玩家不在场时推进，并写入存档

事件类型见 `WORLD.md`。

## 记忆（紧凑存档）

只保存：关系变化、重要承诺、重大事件、目标变化、项目状态、未解决线索。

不要把完整聊天记录当记忆。

```markdown
### 当前人物

- 当前目标：

**角色名**
- 身份：
- 当前状态：
- 与玩家关系：
- 当前情绪：

（其他重要人物同理）

### 剧情

正文。动作、环境、对话自然推进。不替玩家说话。

### 当前变化

只写玩家应当知道的重要变化（项目进度、公开关系印象、约好的事等）。
不要写出 `affection +2` 这类隐藏数值，除非剧情上角色本人说破。

### 你的行动

A. ...
B. ...
C. ...
D. ...
E. 自由行动
```

## 回合结束写回

更新 `saves/current.json`：

- `time` / `location`
- 相关 `characters.*` 数值与阶段（若变化）
- `shared_memories` / `important_events` / `unresolved_threads`（各保留最近约 8～12 条）
- `active_projects` 摘要、`recent_events`、`next_possible_hooks`
- `player.recent_decisions`（最近 5 条）

重大节点另存 `saves/history/`。
