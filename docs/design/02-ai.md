# SPEC 02｜AI Agent

> Phase 2\
> 依赖：Phase 1

## 1. Scope

-   懂宝 AI 对话
-   PydanticAI Agent
-   Tool Calling
-   宝宝 Context
-   历史会话
-   RAG
-   专业来源
-   结构化回答
-   文字 / 语音 / 图片输入（复用 Phase 1 ASR / Vision）

不包含 Phase 1 的记录识别/RecordDraft 保存逻辑、哭声专用模型和主动 Push。

## 2. 核心体验

页面必须明确：

``` text
懂宝 AI
正在结合：小米粥 · 当前月龄
```

AI 回答不是通用育儿答案，而应在有依据时使用当前宝宝档案和近期记录。

## 3. Agent Runtime

``` text
User Input
→ Context Builder
→ PydanticAI Agent
→ Tool Calling / RAG
→ Tool Result 回给 Agent
→ 继续推理
→ 无 Tool Call
→ Structured Response
```

工具执行结果必须回到 LLM；只有模型不再调用工具时，本轮 Agent Loop
才结束。

## 4. Context

可使用： - baby profile - recent feeding - recent sleep - stool /
diaper - growth - vaccine / medication - Phase 3 cry results -
conversation history - AI memory - RAG knowledge

Context 按问题动态装配，避免把全部历史塞入 prompt。

## 5. Tools

首批：

``` text
get_baby_profile
get_daily_feeding
get_recent_sleep
get_recent_records
get_growth_history
search_parenting_knowledge
```

Tool 只暴露业务能力，不允许 LLM 直接访问 ORM/SQL。

## 6. RAG

``` text
query
→ embedding
→ pgvector retrieval
→ chunks + source metadata
→ Agent
→ answer + citations
```

MVP 不引入独立向量数据库。

RAG 数据：

``` text
rag_document
rag_chunk
embedding
source_title
source_url
publisher
published_at
review_status
```

无可靠来源时不得虚构引用。

## 7. Structured Output

建议：

``` python
class ParentingAnswer(BaseModel):
    summary: str
    reasons: list[str]
    baby_context: list[str]
    actions: list[str]
    watch_for: list[str]
    sources: list[SourceRef]
    related_record_ids: list[UUID]
    medical_disclaimer: str | None
```

UI 优先渲染卡片，不全部显示成长文本。

## 8. Conversation

``` text
ai_conversation
ai_message
```

message 保存
role、content、structured_payload、model、usage、created_at。

短期 Context 初期可从 PostgreSQL 获取；达到性能需求后再引入 Redis。

## 9. 多模态输入

Phase 2 不重复建设 ASR / Vision 基础设施，复用 Phase 1 已建立的 Provider：

``` text
语音问题 → Phase 1 ASR → user text → Agent
图片问题 → Phase 1 Vision / multimodal provider → observations → Agent
```

Phase 2 的新增价值是把这些输入放入宝宝 Context、Conversation、Memory、Tool Calling 与 RAG 中推理。

RecordDraft 与正式保存规则始终归 Phase 1 Record 模块所有。图片和语音输入只作为当前问题信息，不自动生成正式业务记录；如果用户明确要“记录下来”，仍调用 Record 模块生成 Draft，并要求用户确认。

## 10. Safety

-   不诊断疾病
-   危险信号优先就医
-   不伪造宝宝数据
-   不把相关性表达成因果
-   数据不足明确说明
-   专业事实尽量有来源
-   高风险健康问题减少个性化推断

## 11. Observability

Langfuse 记录： - trace - model call - tool call - latency - token
usage - error - RAG retrieval metadata

敏感媒体和完整隐私数据不直接写入 Trace。

## 12. Acceptance Criteria

-   AI 知道当前 baby_id
-   可调用真实记录 Tool
-   Tool 结果回到 Agent 后继续推理
-   RAG 回答可展示真实来源
-   没有数据时不虚构
-   Structured Output 可稳定渲染
-   单 Tool 失败有可理解的降级回答
