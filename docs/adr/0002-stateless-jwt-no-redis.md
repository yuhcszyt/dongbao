# ADR 0002: 用无状态 JWT，不引入 Redis

- 状态: 已接受（2025-09-15，grill 达成定稿，Q&A 中明确质疑并论证）
- 决策人: 项目负责人 + AI

## 背景

常规 session 方案需要 Redis 存会话。质疑点：微信登录是否也必须 Redis？

## 决策

凭证用 HS256 签名的 JWT（标准库 HMAC，不引第三方库），30 天有效期，服务端零存储：

| 传统需要 Redis 的场景 | 本项目是否沾 | 处理 |
|---|---|---|
| 短信验证码（5 分钟有效期存储） | 否（微信登录，无短信） | 不需要 |
| 主动吊销 token（踢人/封禁） | 不做此功能 | 不需要 |
| 注销账号后 token 必须立即失效 | 是 | 鉴权依赖每次查用户表拿 family_id，用户被删即 401——吊销是查询的副产品 |
| 微信 session_key 持久化 | 否（不解密手机号/用户信息） | 不需要 |

## 后果

- 正面：docker-compose 不新增组件，无 Redis 备份/运维负担
- 代价：不支持"单点强制下线"
- 升级路径：将来若要短信验证码、登录限流或强制下线，再引 Redis 作为拒绝名单/验证码存储，JWT 方案保留
