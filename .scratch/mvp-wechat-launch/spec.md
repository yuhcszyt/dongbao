# 懂宝 MVP 上线：微信静默登录 + 首页 / 记录页 / 档案页

## Problem Statement

现在的懂宝把「开发期的记录功能」直接暴露给真实家长：没有登录，服务端用环境变量里写死的家庭 ID 和用户 ID 代替鉴权，`docker-compose` 里那套 `TEST_FAMILY_ID` / `TEST_USER_ID` 就是全部的身份体系。

后果，从用户角度看：

- 任何打开小程序的人都在读写**同一份**宝宝数据。家长 A 能看到、能改、能删家长 B 的宝宝档案和全部记录，包括语音和照片。
- 家长第一次进来不知道怎么开始：没有"认识一下宝宝"的入口，也没有"这台设备属于哪个家庭"的概念。
- 上线版本要求的三个页面还不成形——首页和记录时间线挤在同一个页面里，宝宝档案没有独立入口，"编辑档案"体验缺失。
- 微信平台合规要求的**注销账号**入口在小程序里根本不存在（服务端已写，但没有任何调用它的路径）。
- 服务端其实已经有一套微信登录 + 家庭 + JWT 的代码写完了，但它没有被接进应用，前端也没有任何 token 概念——等于白写。

一句话：**东西能跑，但不能给真人用。**

## Solution

让家长用一个真实存在的、可撤回、互相隔离的账号打开懂宝：

- 家长打开小程序即完成**静默登录**——没有登录页、没有按钮、没有密码和手机号（`wx.login` code → `jscode2session` 换 openid → 登录即注册 → 发 30 天 JWT）。之后所有请求都自带这个凭证。
- 每个账号落在自己的**家庭**里，宝宝、记录、媒体全部挂在家庭下。别人拿不到、改不到、删不到。
- **首页**（原型 01）让人一眼知道宝宝现在怎么样：宝宝行（点进档案）、问候语、今日记录指标、快速记录、最近动态 3 条。
- **记录页**（原型 03）是真正干活的地方：7 天日期条 + 任意日期选择 + 类型筛选 + 时间线 + 点按编辑 + ＋添加。
- **宝宝档案页**（原型 09）能看能改，并且提供一个符合微信平台合规要求的**注销账号**入口，注销后账号与该家庭下的宝宝、记录、语音、照片一并删除。
- 开发同学在本地和 CI 里不需要真微信凭证也能跑通全链路：显式开启的开发降级让 `code` 直接充当 openid，生产默认关闭。

## User Stories

登录与会话

1. 作为家长，我打开小程序就能直接看到宝宝的首页，不需要注册、登录、填手机号或点"微信授权"，这样我第一次用就能开始记录。
2. 作为家长，我登录一次之后 30 天内再打开就不用重新登录，这样我不用反复面对登录这一步。
3. 作为家长，如果我的登录已经过期，小程序应当自己重新登一次并把我刚才要做的操作继续做完，而不是甩一个错误给我。
4. 作为家长，如果重新登录也失败（比如微信侧异常或网络问题），我应当看到一句中文提示和重试入口，而不是白屏或者卡在加载中。
5. 作为家长，我的账号被注销之后再次打开小程序，应当被当成一个全新的、干干净净的账号来对待，而不是看到一个报错页面。
6. 作为家长，我在同一个微信下换设备登录，看到的还是同一个宝宝的数据，不需要重建档案。
7. 作为开发者，我在没有配置 `WECHAT_APPID` / `WECHAT_SECRET` 的本地或 CI 环境里显式开启开发降级后，能用任意字符串当作 code 登录成功，从而跑通登录 → 建档 → 记录的完整链路。
8. 作为开发者，生产环境默认**不**开启开发降级，我不会因为忘记关开关而把写死身份的后门带上线。
9. 作为开发者，H5 开发环境下没有 `wx.login` 可用，我仍然能通过同一套接口登录（客户端在非微信环境用本机持久化的开发 code 调同一个登录接口），这样网络层只有一条登录路径、没有环境分支。

数据隔离与安全

10. 作为家长，我只看得到我自己家庭的宝宝、记录和媒体文件，别的家庭的数据不会出现在我的时间线里。
11. 作为家长，我用自己家庭的凭证去请求别人家的宝宝或记录时，得到的应当是"没有找到"，而不是"你没有权限"——不通过错误码泄露别人数据的存在性。
12. 作为家长，我的语音和照片上传到服务端后只有我的账号能取到，别人拿不到。
13. 作为家长，我的 token 里不包含任何明文隐私字段，服务端也不把会话存在 Redis 或数据库里（依据 ADR-0002）。
14. 作为家长，账号一旦注销，我手上的旧 token 立刻失效，不能再用它读到任何数据（依据 ADR-0002 的"吊销是查询的副产品"）。
15. 作为家长，伪造或篡改过的 token 一律被拒，而不是被当成某个真实账号。

宝宝档案与首次使用

16. 作为家长，我第一次进来且家庭里还没有宝宝时，看到的是"先认识一下宝宝"的建档流程，只需要昵称、生日、性别三项。
17. 作为家长，建档时我能选择生日、能选择性别（男宝 / 女宝 / 暂不填），并且生日不能被填成未来日期。
18. 作为家长，昵称或生日没填时提交会被挡住并给出中文提示，而不是提交成功后再报错。
19. 作为家长，建档成功后我立刻进入首页，看到宝宝昵称、月龄和性别，而不是还要手动刷新。
20. 作为家长，我在首页点宝宝那一行能进入宝宝档案页。
21. 作为家长，档案页能查看昵称、生日、性别，其中未填的项显示成"待完善"而不是空白。
22. 作为家长，我能在档案页点"编辑"改昵称、生日、性别并保存，保存后首页和档案页都显示新值。
23. 作为家长，我编辑档案时校验规则和建档时一致，不会出现"建档要求填生日、编辑却允许清空"这种前后不一致。
24. 作为家长，我改档案保存失败时看到中文提示，并且输入的内容不会被清空，我可以直接重试。

首页（原型 01）

25. 作为家长，我打开首页就能看到问候语和"今天怎么样"的今日记录指标：奶量、睡眠分钟、尿布次数、辅食次数。
26. 作为家长，我理解这些数字只代表"已记录的内容"：首页会明确说明没记录不代表没发生，这样我不会拿它当成真实摄入量。
27. 作为家长，我在首页能看到最近 3 条动态，点"查看全部"跳到记录页，这样我不用为了看一眼今天的记录而迷路。
28. 作为家长，我从首页就能一键开始"快速记录"，选录音、拍照或直接点某个记录类型。
29. 作为家长，首页不出现 AI 对话、哭声监测、文章推荐和统计图表区块——MVP 不做这些，首页第一目标是"宝宝现在怎么样"（依据 CONTEXT 上线决策 6）。
30. 作为家长，首页的今日指标会在我新增、修改、删除、撤销一条记录后自动更新，我不需要手动刷新。

记录页（原型 03）

31. 作为家长，我在记录页顶部看到 7 天日期条，并且能点开日期选择器跳到任意一天。
32. 作为家长，我切换日期后看到的是**那一天**的时间线，而不是全部记录，这样补记昨天的事很顺手。
33. 作为家长，我能按类型筛选（全部 / 喂奶 / 辅食 / 睡眠 / 排便 / 尿布），筛选和日期选择可以叠加使用。
34. 作为家长，筛选到某一类但没有记录时，我看到的是"还没有这类记录"的空状态提示，而不是一片空白。
35. 作为家长，我点时间线里的任意一条记录就能进入编辑，改完保存后列表和今日指标同步更新。
36. 作为家长，我能从记录页用 ＋ 按钮新增记录，并支持十类记录（喂奶、辅食、睡眠、排便、尿布、哭闹、身高体重、疫苗、用药、自定义）。
37. 作为家长，我能用语音或拍照生成一条待确认的草稿，确认后才真正存成记录——草稿不会直接进时间线（依据 CONTEXT 术语表：草稿 `RecordDraft` 确认后转为记录）。
38. 作为家长，当语音 / 图片识别未配置或失败时，我能拿到一个可手动填写的草稿，并且我上传的语音或照片不会因此丢失（沿用现有降级行为）。
39. 作为家长，我删除一条记录后能在页面底部立刻撤销，不用去别的地方找回。
40. 作为家长，我能点开记录里的语音播放、点开照片预览，并且这些媒体在鉴权之后依然能正常打开。
41. 作为家长，记录页在数据加载中、加载失败、无数据显示三种状态上都有明确的中文提示。
42. 作为家长，我在记录页的日期条和筛选条上的点击区域足够大（≥48px 高）、文字足够大，因为我可能是爷爷奶奶辈的照护者（依据 PRD 第 3 节"记录模块必须适老"）。

注销账号（微信平台合规）

43. 作为家长，我在宝宝档案页能找到"注销账号"入口。
44. 作为家长，点注销时会先看到二次确认，明确告诉我宝宝档案、全部记录、语音和照片都会被永久删除，不可恢复。
45. 作为家长，我确认注销后，我的用户、家庭、宝宝、记录、草稿和媒体文件都被真正删除（包括服务端本地磁盘上的文件）。
46. 作为家长，注销完成后小程序回到一个干净的初始状态，不会把我静默重登成一个新账号，从而给我"注销没生效"的错觉。
47. 作为家长，注销过程中如果请求失败，我看到的还是一句中文提示，账号不会被删成"删了一半"的状态。

一致性、错误与体验

48. 作为家长，任何请求失败时我看到的都是中文提示（"请先登录"、"登录已过期，请重新进入"、"账号已注销"、"没有找到宝宝档案" 等），而不是英文异常或堆栈。
49. 作为家长，我在弱网下重复点击保存不会产生两条重复记录。
50. 作为开发者，我能从响应里拿到 `request_id`，出问题时可以拿它去日志里定位这一条请求。

## Implementation Decisions

### 应用装配与入口统一（先修断链）

分层重构留下了未闭合的引用，必须先统一到一个入口，否则登录接进来之后没人跑得起来：

- 应用装配集中到一个**唯一的应用模块** `app.main`：创建 FastAPI 实例、注册 request-id 中间件、注册 HTTPException / RequestValidationError 异常处理器（保持现有错误信封 `{"error": {"code", "message", "fields"?}, "request_id": ...}`），并 `include_router` 记录路由与鉴权路由。
- 现状不一致的三处全部改到 `app.main:app`：`docker-compose.yml` 里 server / server-test 的启动命令已经是 `app.main:app`；`apps/server/Dockerfile` 的 CMD 仍是 `app.record.main:app`；`AGENTS.md` 本地启动说明也是 `app.main:app`。
- 测试里的 monkeypatch 目标 `app.main.transcribe_audio` / `app.main.extract_draft` 指向的属性**不存在**（当前 `list_babies` 之外的 provider 符号在记录路由模块里解析），两个用例是坏的。测试必须 patch 真正解析这些符号的模块。
- 鉴权路由目前**没有被 include**，等于死代码，本次接上。
- `alembic/env.py` 只 import 了记录侧模型，`families` / `users` 不在 metadata 里；补上 import，让后续 autogenerate 不会漏表。

### 鉴权依赖与家庭解析

- 抽出**独立的鉴权依赖**，由 `current_user`（解析 Bearer → 校验 → 查用户表 → 返回 `User`）与"当前家庭 ID"组成，记录路由与鉴权路由共用同一份实现，不在两处各写一遍。
- 记录侧所有接口改为依赖该鉴权拿到 `family_id`，删除 `FAMILY_ID` / `USER_ID` 常量以及 compose 里的 `TEST_FAMILY_ID` / `TEST_USER_ID`（约 20 处引用），`created_by` 写真实用户 ID。
- 鉴权失败语义（保持现有文案，客户端与测试都依赖它们）：
  - 缺少 / 格式不对的 Authorization → 401 `missing_token`「请先登录」
  - 签名不合法或已过期 → 401 `invalid_token`「登录已过期，请重新进入」
  - 用户已不存在（注销后）→ 401 `invalid_token`「账号已注销」
- 跨家庭访问一律返回 **404 + 现有 not_found 错误码**（`baby_not_found` / `record_not_found`），不引入 403，不泄露存在性。
- JWT 细节维持 ADR-0002 不动：HS256、标准库 HMAC、30 天、服务端零存储、吊销靠查用户表。

### 微信登录接口与开发降级

- `POST /api/v1/auth/wechat` 契约不变：入参 `code`，出参 `token` + `user_id`；首次登录创建 `Family` + `User`，再次登录复用。
- **开发降级**（本次新增决策）：仅当显式设置 `DEV_LOGIN=1` 时，跳过 `jscode2session`，直接把 `code` 当 openid 使用；未设置时保持现有行为（缺 `WECHAT_APPID` / `WECHAT_SECRET` → 502 `wechat_login_failed`）。生产环境不得设置该变量，且在启动日志里提示当前处于哪种模式。
- 微信侧失败归一为 502 `wechat_login_failed`，文案不含任何上游返回的原始错误细节。
- 客户端在非微信环境（H5 开发）用本机持久化的开发 code 调用**同一个**登录接口，网络层不出现环境分支。

### 客户端会话（新增一个纯模块 seam）

- 新增一个**纯会话模块**，负责：token 持久化（`uni.getStorageSync` / `setStorageSync`）、启动时静默登录、给请求附带 `Authorization: Bearer`、401 后重登并**最多重放一次**原请求、注销后清空本地状态。它不导入任何页面组件，可以被 vitest 直接单测。
- 启动时序：读取本地 token → 有则先当已登录用 → 首次请求若 401 则重登 → 重登失败则进入"需要重试"的可恢复状态。不做登录页 UI（CONTEXT 上线决策 2：静默重登）。
- 注销后**不自动重登**：清 token 并把应用置于干净的初始状态（新会话要等下一次冷启动或显式操作），避免"注销即重新注册"的错觉。
- 统一网络层是所有请求（含 `uni.uploadFile`）带 token 的唯一位置，页面不自己拼 header。

### 媒体文件的取用方式（重要约束）

- `uni.previewImage` / `uni.createInnerAudioContext` **无法设置请求头**，所以媒体读取接口不能要求 Bearer。决定：媒体 GET 保持免 token，以**不可猜的 UUID 作为能力凭证**，但必须校验该媒体所属家庭与当前 token 家庭一致——即媒体 URL 只在"已鉴权的列表/详情响应"里被下发，拿到 URL 的人只拿到这一个文件。
- 上传接口（`uni.uploadFile` 可设 header）走正常 Bearer 鉴权。

### Schema 与迁移

- 不新增表、不新增列：`families` / `users` 已由迁移 0002 建好，`baby` / `record` / `media` / `draft` 的 `family_id` 列已存在。
- 迁移方向不变：`0002_auth` 的 `down_revision` 保持 `0001_record_phase1`；本 spec 不新增迁移。
- 唯一与"数据"有关的改动是**运行时语义**：`family_id` 从环境变量常量变成真实家庭，存量开发数据视为可丢弃。

### 客户端页面结构

- 页面拆分为：**首页**（原型 01）、**记录页**（原型 03）、**宝宝档案页**（原型 09）。现在的单页实现同时承担了首页和记录页，需要拆开。
- 导航：底部 tab 只保留 **首页 / 记录**；**懂宝 AI tab 隐藏**（CONTEXT 上线决策 1）；宝宝档案页从首页宝宝行进入（CONTEXT 上线决策 6），记录页顶部也保留一个入口。
- 记录页的日期筛选**沿用 CONTEXT 上线决策 5**：客户端按本地日期过滤，不给记录列表接口加 `from` / `to` 参数。代价是列表随数据量增长会变重，见 Further Notes。
- 首页今日指标继续用现有的 `daily-summary?date=&timezone=` 接口（携带客户端本地日期与时区作参数），不新增接口。
- 记录类型的图标、标签、描述、每日汇总归一化等纯逻辑继续住在记录领域的纯模块里（当前 `domain.ts` 与 `domain.test.ts` 已经是这个形态），页面只做取数与渲染。
- 档案页的字段范围：**昵称、生日、性别**（与建档三项一致）。原型 09 里的"喂养方式""过敏信息"不进 MVP，见 Out of Scope。
- 注销入口放在档案页底部，二次确认弹窗文案需明确列出会被删除的内容。

## Testing Decisions

### 什么算好测试

- 只测**外部可观察行为**：HTTP 状态码、错误信封里的 `code` 与用户可见文案、跨家庭不可见性、注销后副作用、纯函数的输入输出。不测 ORM 查询写法、不测私有函数、不 assert SQL、不依赖实现细节的内部调用顺序。
- 隔离性用"两个家庭互相看不见"来表达，这是产品承诺，不是实现细节。
- 客户端纯模块的测试断言**契约**（哪些输入合法、401 后重放恰好一次、注销后本地状态被清空），不断言内部存储键名以外的实现细节。

### 服务端测什么（复用现有 seam）

Seam 就是现有的 HTTP 边界：`TestClient(app)` + autouse 的数据库清理 fixture + monkeypatch 掉外部依赖。新增/改造：

- 登录：`/auth/wechat` 首次调用建 Family + User；同一 code 再调复用同一 `user_id`，且两次的宝宝互相可见（同家庭）。
- 鉴权：无 Authorization / 篡改 token / 过期 token → 401 且 `error.code` 分别为 `missing_token`、`invalid_token`。
- 隔离：以第二个 openid 登录，交叉访问第一个家庭的 baby / record / media / draft，全部 404，且返回的是 not_found 错误码而不是 403。
- 注销：`DELETE /me` 返回 204；随后旧 token 请求 → 401「账号已注销」；该家庭的 baby / record / draft / media 行与磁盘媒体文件都已清掉。
- 记录全链路：把现有 `test_records.py` 的四个场景（十类记录 + 时间线 + 今日汇总 + 编辑 / 删除 / 撤销；语音草稿需确认且保留来源；Provider 失败返回可编辑草稿且不丢媒体；拒绝 payload 类型不匹配与非法上传）**改为带 token 调用**，作为"鉴权重构没弄坏原有行为"的回归网。
- 清理 fixture 需要扩展：当前只清记录侧的表，加了 users / families 之后必须一起清，否则第二个用例会撞上 unique openid。

### 客户端测什么（一个新增 seam）

- 复用现有 vitest 纯模块 seam：`apps/client/src/features/record/domain.test.ts` 是唯一先例（import 纯模块、断言返回值）。
- 新增**会话模块**的测试，同一风格：静默登录成功后有 token、401 时重登并重放一次且只重放一次、重放后仍 401 不无限循环、注销后本地状态被清空且不自动重登。
- 记录领域纯模块（日期条构造、按日/类型过滤、汇总归一化）继续扩测。
- **不引入**组件级测试基建（`@vue/test-utils` / uni 组件 mock）；页面交互仍靠开发者工具手工验证，与现状一致。

### 跑法（沿用现有命令）

- 服务端：`docker compose --profile tools run --rm server-test`（`alembic upgrade head && pytest`，数据库是 `postgres-test` 的 tmpfs 实例）。
- 客户端：`docker compose --profile tools run --rm client-test`（`npm run typecheck && npm test`）。
- 端到端人工验收：`docker compose up --build`，H5 打开 5173 走开发降级登录；微信开发者工具导入 `apps/client` 看真机形态。

## Out of Scope

- **家庭共享与多家长**：邀请码、成员列表、权限与审计全部留在 Phase 5（ADR-0001 明确）。
- **多宝宝切换**：UI 只做一个宝宝；表结构天然支持，但本次不做切换入口。
- **主动退出登录**：只做注销，不做"退出登录"按钮（CONTEXT 上线决策 11）。
- **头像与昵称同步**：不取微信用户资料（ADR-0002：不解密用户信息，也就不需要持久化 session_key）。
- **短信验证码、登录限流、强制下线（踢人 / 封禁）**：需要时才引 Redis，JWT 方案保留。
- **AI 对话、哭声识别、文章推荐、统计图表页**：MVP 隐藏，首页不出现这些区块。
- **档案页的"喂养方式""过敏信息"**：原型 09 有这两个字段，但 schema 里没有，也不在术语表定义中；引入需要单独决策，本次不做，档案页只呈现昵称 / 生日 / 性别。
- **记录列表的后端分页 / 日期范围参数**：依据 CONTEXT 上线决策 5 走客户端过滤；`from` / `to` 与分页留到数据量增长时再开。
- **正式域名、HTTPS、隐私政策文本落地与小程序审核材料**：属于发布流程，由人执行；本 spec 只保证「有注销入口」这一条合规硬要求落地。
- **数据导出 / 迁移**：不提供注销前的数据导出。
- **存量开发数据的保留**：`TEST_FAMILY_ID` 那批数据视为可丢弃，不做迁移。

## Further Notes

- **契约一致性**：本 spec 与 ADR-0001（登录提前进 MVP、家庭共享仍留 Phase 5）、ADR-0002（无状态 JWT、不引 Redis）一致，无冲突。术语沿用 CONTEXT.md 术语表（用户 / 家庭 / 宝宝 / 记录 / 草稿 / 凭证），不要漂移到同义词。
- **已知断链清单（实施时应一并收口）**：
  1. 鉴权路由未 `include_router`，登录接口在当前构建里根本访问不到。
  2. 入口三处不一致：compose 与 AGENTS.md 写 `app.main:app`，Dockerfile 写 `app.record.main:app`。
  3. 测试 monkeypatch 目标 `app.main.transcribe_audio` / `app.main.extract_draft` 不存在，语音与 Provider 失败两个用例是坏的。
  4. `alembic/env.py` 未 import 鉴权模型，autogenerate 看不见 `users` / `families`。
  5. 测试清理 fixture 不含 `users` / `families`。
  6. `providers.py` 的 `_secret()` 引用未定义变量（`if not value:` / `return value`），未配置凭证时抛 `NameError` 而非 `ProviderUnavailable`，识别降级契约整条坏掉；现有用例把 `transcribe_audio` / `extract_draft` 全 patch 掉，所以测试看不见（2026-09-16 验收票据 01 时发现，归入票据 09 一处修）。
- **客户端现状**：`pages.json` 只注册了一个页面，`services/api.ts` 完全没有 token 概念，全仓搜不到 `wx.login`；登录模块与页面拆分是本次的主要前端工作量。
- **媒体免 token 的取舍**：以 UUID 作能力凭证意味着 URL 泄露即文件泄露。MVP 接受该风险（文件不可枚举、传输层后续上 HTTPS）；若要更严，后续可改为短时效签名 URL，届时只需改下发 URL 一处。
- **记录页客户端过滤的代价**：接口返回该家庭全部记录，页面按本地日期过滤。家长记录量到数千条时首屏会变慢，届时优先加 `from` / `to` 参数而不是引入分页 UI。
- **开发降级的安全边界**：`DEV_LOGIN=1` 会让任意字符串都能换到一个合法 token，因此必须默认关闭、仅在本地与测试环境显式打开，并在启动日志中打印当前模式。
